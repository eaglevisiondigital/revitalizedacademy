## Security and release boundary

B2 invokes only existing `list_vitality_roadmap_preparation` and `get_vitality_roadmap_preparation` read RPCs. B1 enforces verified current sessions, private-health permission and contact scope. Denial, logout, late responses and account changes clear workbench private DOM/state. Source text renders through textContent, not HTML. Source review is separated from synthetic calculation and never populates the simulation/export automatically.

The calculator's `provenance` label is not proof that a manually entered JSON value is synthetic; it is a simulation contract, not an authorization control. No server accepts candidate results as approved scores, reports or release authority. `policyApproved=false`, `releaseEligible=false`, `clientReport=null` remain explicit. The B1 database trigger/approval endpoint remains the authoritative release block.

No migrations, Edge updates, permissions, roles, invitations, emails, payment state, participant source records or approved/released reports changed. Production public allowlist and all 395 production build files are byte-identical to B1. B2 lives only in an isolated manual staging draft; beta primary remains separate.
