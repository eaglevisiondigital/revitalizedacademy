# B6 feasibility preflight — source code only, no participant processing

The current B3 `scoreActualSource()` throws. B5 `analyze()` returns contextual coverage with null actual scores/stages. B2.1 expects a numerical measurement sheet, not the 743-field saved questionnaire. The code audit yields **0/11 complete health Driver scores and 0/1 complete separate Budget indicators** from the current questionnaire contract, even for an otherwise completed Adult/Myself submission. Consequently no defensible complete aggregate or Spectrum is available today. No hosted participant was searched, read, counted, selected or scored; actual eligible-person counts are deliberately not asserted.

## What can be supported

- Preserve submitted selected strings/numbers, explicit zero/null/unknown, branch conflicts and inapplicability without rewriting answers.
- For an applicable, conflict-free symptom screen containing only `None of these`, describe a proposed isolated zero-burden conversion, but keep its numerical value withheld until captured question semantics and rubric provenance are independently established. This is not a zero Driver score, a diagnosis, proof of symptom-free health, or approved policy.
- For an applicable current question explicitly asking consistency and using the engine's exact consistency labels, describe the proposed pinned label-to-number rule, with the numerical value withheld for revision-unverified captures. Habit role/definition/opportunities, factual proficiency and a full lifestyle score remain unsupported. No average of these fragments is presented as a Driver score.
- Preserve all other reported symptom/functional/budget context qualitatively. In particular `How disruptive?` is not automatically independent intensity and daily impact. A confidence response is not demonstrated factual proficiency.

The adapter is versioned and pins the registry, B4 coverage, B5 contract, B2/B2.1 file hashes and candidate configuration. Source content fingerprints remain server-owned and are never client-supplied authority. Original answers are immutable. Proposed source conversions are not adopted policy. Historical-only, child/proxy, incomplete, malformed, ambiguous and changed sources fail closed. A version label or a matching field name is not proof of historical semantics. The strict result explicitly withholds numerical Driver/overall/stage outputs while showing source-supported fragments and all blocking evidence.

## Required founder/owner decisions before real numerical calibration

1. Approve Driver-specific habits, foundational/supporting roles, applicable opportunities and factual proficiency evidence.
2. Define or collect exact current finding days, independent intensity/impact/function, exact persistence and non-duplicated ownership. Choose whether new measurements require a new questionnaire rather than assigning them to old answers.
3. Establish verifiable questionnaire revision/wording provenance for any historical source; otherwise exclude it from numerical scoring and use only clearly labeled reference-context/manual review.
4. Independently set expected score ranges, classifications, priorities and rationale; resolve A/B/C discrepancy and poor-habits/no-symptom Chaos before policy adoption.
5. Approve the new B6 experimental-processing purpose/SOP/privacy authority separately from B4's no-scores SOP. Approve one exact verified source first, then at most three more; each needs its own source pin, B4 read-only cohort, B5 compute grant and operator B6 authorization for at most14 days.
6. Separately approve private feedback-write authority if durable manual comparisons are desired. This does not activate B4 drafts, report approval, release or email.

Optional conditional experiments require explicit founder-entered assumptions, remain detached from answers and never fill a missing actual measurement. Their arithmetic is an experiment, not an actual participant score or policy change.
