## Database and authorization contract

Private tables `roadmap_b4_cohort_events`, `roadmap_b4_versions`, `roadmap_b4_audit` have RLS, no direct browser/service-role table or sequence grants, and UPDATE/DELETE/TRUNCATE rejection. No browser policy permits direct access. The sole authenticated RPC is `public.roadmap_b4(action,report,payload)`; private helpers have empty search paths and revoked execution grants.

Every RPC requires the production JWT issuer, an authenticated nonanonymous caller, a live matching `auth.sessions` row, verified/unbanned/undeleted Auth identity, exact Justyn/Elle founder email **from Auth, never user_metadata**, current active completed Owner, All People scope, effective `health.private.view`, `crm.view`, and current contact scope. Draft writes additionally require `health.progress.manage` and explicit cohort `allow_drafts=true`. Ordinary Owner/Admin/Coach/member/anonymous/service-role callers are denied. Supabase verifies bearer signatures/expiry; SQL freshly checks session and authoritative staff state rather than stale JWT role claims.

Cohort is **empty by default**. The operator-only `private.roadmap_b4_set_cohort` has no public/authenticated/service-role execution grant. Each approved/revoked event records the verified founder approver, approval/SOP reference, exact report/source hash and whether drafts are authorized. It does not grant staff permissions. Cohort authorization must be separately obtained; this task does not approve one. Read-only approval defaults `allow_drafts=false`. List uses generic cohort labels and returns no answers/names; source is fetched only after opening an explicitly approved report.

Source read requires the exact existing report/contact/workflow/draft anchors, completed verified secure draft and completed workflow, explicit Adult/Myself with exactly one selected person answer, secure-snapshot-v1 and matching source fingerprint. Historical summaries, child/proxy, incomplete, unmatched, unregistered or guessed records are refused. The fingerprint covers canonical snapshot **and original final-form summary/flags**, not changing contact display metadata. Reads never update originals and do not duplicate raw answer snapshots in derivative tables. Audit records IDs/hashes/actions, never answer payloads.

Pinned coverage: `b4-source-coverage-20261016-v1`; registry SHA-256 `2f67c193c2e69b54d61a44599bf9308ca27d317f2bdb748adbeaedfdabe92ced`; 743 field references / 190 symptom observations. The reference code is unchanged from B3 and current production. The source's provenance is explicitly **version_label_only**, not a fabricated historical code hash. Raw labels, unknowns, explicit zeros, applicability conflicts and unsupported questions remain distinct. No frequency-to-days or duration midpoint conversion; no confidence-to-factual-proficiency conversion. Budget is separate. Overall/Driver scores and stages remain null/unscored.

Draft saves are distinct persisted derivative writes. They preserve original answers, require rationale/evidence IDs and explicit change reasons, validate correction proposals without applying them, and append a version and audit atomically. Only draft / needs_clarification / under_review states exist. Expected version plus actor/content/cohort-bound idempotency prevents overwrites/replays. Report advisory locking serializes saves and cohort changes. Source changes require renewed explicit source approval followed by regeneration; previous drafts/hashes are retained, never rewritten. Old-version previews disclose if their source pin differs from the current pin; they do not reconstruct an earlier overwritten source.

There is no scoring, approval, release, email or participant-delivery action. Structured score/stage injection is rejected; nullable score/stage columns cannot hold values. No report approval endpoint or notification outbox integration is installed.
