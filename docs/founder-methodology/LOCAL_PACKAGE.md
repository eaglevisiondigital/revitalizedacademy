## Local questionnaire specification

`config/roadmap-questionnaire/vnext-draft.json` is not referenced by live intake or bundled in the report Function. It retains exact original requested questions beside proposed wording, options, conditions, context links, placement and stable IDs. New options not provided by the founder are explicitly proposed formats for Owner review.

58 source requests resolve into 4 reused request groups and 51 proposed addition/detail blocks. Consolidating the shared exposure inventory and swelling-location prompt removes three repeated prompts. Two independent symptom measurement templates bring the logical delta to 57 blocks including reuse. This is not 57 mandatory additions.

There are 84 new non-template input definitions, plus two conditional inputs for each of 190 existing symptoms (380 possible identifiers). The projected schema has 1,207 field definitions including the unchanged 743; this is not a 1,207-question mandatory assessment. Only selected applicable symptoms get their own qualifiers. Old disruption answers are not renamed/backfilled. The number of displayed questions depends on branches, explicit equivalent existing coverage and unknown/declined/not-applicable choices.

The four reused requests reference nocturia, yellowing, separate morning headache/brain-fog follow-ups, and straining. No general fatigue response substitutes for brain fog. Same symptom and same recall period are required; a current 30-day screen does not answer a lifetime-history question. Free-text presence alone never proves equivalent coverage.

Three required ownership distinctions remain explicit: original symptom ownership is unchanged; new fields are unscored context; cross-Driver reuse does not create independent burden. The new version will need separately approved capture, retention, historical-version handling, source registry/adapters and UI integration before any live issuance. No one must retrospectively complete it for the next comparison report.
